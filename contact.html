A useful first pilot

Keep the scope narrow enough to produce a decision.

A focused account and a known rule set make the output easier to interpret than a broad, undefined “risk system test.”

Define the rule

Agree which breach matters: daily loss, trailing drawdown, target state or another explicit condition.

Observe the account

Connect with the minimum read permissions required for the selected venue.

Collect events

Record the breach instant, your existing system response and the exchange-confirmed resulting state.

Review evidence

Use the resulting distribution and failure cases to decide whether architecture changes are justified.
